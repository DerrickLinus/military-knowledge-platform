# ADR-0002：前端生成回答的 Word 和 Markdown 文档

- 状态：提议（工程初稿，待实施验证）
- 日期：2026-09-08
- 关联 Issue：[WK-002 / #5](https://github.com/DerrickLinus/military-knowledge-platform/issues/5)

## 背景

用户需要将聊天中的单条回答导出，用于线下留存、汇报和二次编辑。首版同时提供 Word 和 Markdown，内容包括对应问题、最终回答与引用来源，通过回答操作区的统一菜单选择格式。

当前前端已经持有回答 Markdown、问题和引用数据，普通回答与 Agent 回答分别拥有操作区。现有 `marked` 可承担 Markdown 解析；`docx-preview` 是预览依赖，不能替代生成方案。

## 决策

采用前端本地生成方案，共享内容整理与引用映射逻辑，再分别生成 `.docx` 和 UTF-8 `.md`。

- Word 拟使用 `docx` 库，将 `marked` tokens 转换为原生段落、标题、列表和表格，实施时验证版本和构建兼容性。
- Markdown 保留原有结构，转换项目自定义引用标签并附加标准 Markdown 来源列表。
- Word 生成器按需加载，通过浏览器 Blob 下载，不调用外部转换服务。
- 统一按钮悬停展示两种格式，同时支持点击、触屏和键盘操作。
- 只导出已完成的最终回答，不采用 Agent thinking 回退作为导出正文。
- 首版不增加服务端导出接口、持久化导出文件或数据库字段。

## 原因

- 两种格式使用相同的问题、正文和来源，共享内容整理可避免导出结果不一致。
- 数据已经在聊天页中，前端方案改动集中，不需要额外获取完整会话或重新调用模型。
- Word 原生结构适合编辑和排版，Markdown 适合归档、版本管理和再次处理。
- 导出时动态加载生成库，有利于控制聊天页首次加载成本。

## 备选方案

| 方案 | 评估 |
|---|---|
| 后端 Go 新增导出接口 | 便于集中模板和批量任务，但首版需要增加接口、权限校验及部署改动，暂不采用 |
| 页面 HTML 转 Word | 可以复用部分展示结果，但需剥离交互 DOM，且自定义引用与复杂样式仍需适配，暂不作为主路径 |
| 仅导出原始 Markdown | 实现简单，但不能满足 Word 编辑需求，也不能直接处理项目自定义引用标签 |

## 已知限制

- 需要维护受支持的 Markdown tokens 到 Word 结构的映射，未知内容应有可读回退。
- Word 首版不嵌入图片、不生成原生公式或 Mermaid 图像；图片保留说明和链接，公式与图表保留源码。
- 字体和分页效果受 Word/WPS 客户端环境影响，必须进行实际文件验收。
- 历史消息可能缺失问题或来源，导出应如实体现可用信息，不推测补齐。
- 内部资料链接仍依赖访问环境及权限，导出文件不等于离线资料包。
- 大型回答的生成会占用浏览器内存和执行时间，需要通过样本评估上限。

## 后续方向

- 根据需求增加图片嵌入、公式和图表转换。
- 扩展整段会话批量导出、文档模板和 PDF。
- 当批量任务或统一模板管理成为主要需求时，重新评估后端导出服务；根据实测决定是否引入 Worker。
