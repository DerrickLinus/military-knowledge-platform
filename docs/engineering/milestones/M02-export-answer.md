## 阶段目标

用户可在主聊天页通过统一导出按钮选择 Word 或 Markdown，下载包含对应问题、最终回答及引用来源的可编辑文档。覆盖普通问答、Agent 问答及历史回答。

- 已形成开发日志、技术决策和里程碑初稿。
- 导出代码、依赖调整、自动化测试及客户端验收均未完成。

## 个人负责内容

计划覆盖需求梳理、导出内容模型、Markdown/Word 转换、引用映射、工具栏交互、测试与工程交付记录；实际完成情况在开发后更新。

## 关键技术问题

- 普通回答与 Agent 回答数据路径不同，需要准确选取对应问题和最终回答，排除思考内容。
- 自定义引用标签需要转换为文档可读编号，来源去重后仍需保持正文与文末列表一致。
- Word 必须生成真实且可编辑的文档结构，处理中文、嵌套列表、代码和长表格。
- 悬停菜单同时需要支持点击、触屏及键盘，避免仅鼠标可用。

## 测试与验证

以下为验收清单，尚未执行。

- [ ] 两类回答操作区均提供 Word/Markdown 菜单，历史回答可用。
- [ ] 回答完成前不允许导出，生成期间防止重复触发，失败后可重试。
- [ ] 悬停、点击和键盘均可完成格式选择，移动端菜单不溢出或遮挡关键操作。
- [ ] 两种文件均包含正确问题、完整最终回答和可用引用来源，无思考过程和调用日志。
- [ ] 正文来源编号与文末列表对应，重复来源正确归并，缺失来源有合理回退。
- [ ] Word 保留标题、列表、表格、链接和代码结构，中文及长文本无明显溢出。
- [ ] Markdown 为 UTF-8，保留结构和代码围栏，项目引用标签已转换。
- [ ] 文件名带消息标识和时间戳，扩展名与真实格式一致。
- [ ] 导出定向测试、相关工具栏回归、国际化检查、类型检查和生产构建通过。
- [ ] 浏览器实际下载成功，Word/WPS 打开无修复提示且内容可编辑，Markdown 编辑器可正常读取。
- [ ] 记录实际验证环境、命令、客户端版本和未解决限制。

## 前后效果对比

- 之前：回答操作区没有 Word/Markdown 文件下载入口。
- 预期：用户悬停或点击导出按钮，选择格式即可保存当前问题、回答和来源，无需手工整理。

## 性能与兼容性

- 计划仅修改前端，不需要数据库迁移或新增后端接口，不触发 LLM。
- Word 生成库按需加载，Markdown 使用共享内容数据直接生成。
- 验证大回答生成耗时与构建产物变化，具体结果待实施后记录。
- 延续现有嵌入模式边界，首版不在嵌入页和小程序新增入口。

## 已知限制

- 单条回答导出，不包含整段会话或批量导出。
- Word 中图片保留说明和链接，公式及 Mermaid 保留源码；不承诺页面像素级还原。
- 不打包附件和内部资料，资源链接不保证离线可访问。
- 历史消息缺失数据时仅导出可用内容，不补造问题或引用。
