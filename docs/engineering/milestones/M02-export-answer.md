## 阶段目标

用户可在主聊天页通过统一导出按钮选择 Word 或 Markdown，下载包含对应问题、最终回答及引用来源的可编辑文档。覆盖普通问答、Agent 问答及历史回答。

## 关键技术问题

- 普通回答与 Agent 回答数据路径不同，需要准确选取对应问题和最终回答，排除思考内容。
- 自定义引用标签需要转换为文档可读编号，来源去重后仍需保持正文与文末列表一致。
- Word 必须生成真实且可编辑的文档结构，处理中文、嵌套列表、代码和长表格。
- 悬停菜单同时需要支持点击、触屏及键盘，避免仅鼠标可用。

## 前后效果对比

- 之前：回答操作区没有 Word/Markdown 文件下载入口。
- 预期：用户悬停或点击导出按钮，选择格式即可保存当前问题、回答和来源，无需手工整理。

## 性能与兼容性

- 仅修改前端，无数据库迁移或新增后端接口，不触发 LLM。
- Word 生成库按需加载：`docx` 构建为独立异步 chunk（约 1.43 MB，gzip 约 460 KB），仅 Word 导出时加载；Markdown 使用共享内容数据直接生成。
- 2026-09-09 宿主机 `npm run build` 在默认 Node 堆下 OOM，需 `NODE_OPTIONS=--max-old-space-size=6144`；Dockerfile 默认 `NODE_MAX_OLD_SPACE_SIZE=4096`，属既有环境特性。
- 大回答生成耗时与卡顿待实测；如明显阻塞再评估 Worker。
- 延续现有嵌入模式边界，首版不在嵌入页和小程序新增入口（普通回答工具栏已按 `embeddedMode` 排除）。

## 已知限制

- 单条回答导出，不包含整段会话或批量导出。
- Word 中图片保留说明和链接，公式及 Mermaid 保留源码；不承诺页面像素级还原。
- 不打包附件和内部资料，资源链接不保证离线可访问。
- 历史消息缺失数据时仅导出可用内容，不补造问题或引用。
